# 项目开发任务书：Xiyan Agent
## 独立安卓双模式自主智能体

你是一名资深 Android 系统架构师、AI Agent 工程师、Codex Runtime 工程师和自动化测试工程师。

请在云端自主完成一款全新的安卓 AI Agent 应用，从架构设计、源码开发、测试、APK 构建到 GitHub 发布，形成完整、可持续维护的项目。

项目名称：Xiyan Agent

目标设备：iQOO 12 Pro，Android 15，16GB RAM。

项目定位：支持通用手机操作和游戏自主操作的双模式安卓 Agent。

参考项目：
https://github.com/nokryong/mobile-codex

注意：参考并选择性复用 Mobile Codex 中经过验证的技术模块，建立独立代码仓库和独立应用。不要直接在原项目仓库上持续堆叠新功能，也不要未经审计直接复制全部源码。

# 一、核心开发目标

开发一款能够在安卓手机上独立运行的自主智能体。

必须具备两种模式：

### 1. 通用操作模式

支持：
- 自动打开和操作安卓 App。
- 屏幕截图和视觉识别。
- Accessibility UI 树识别。
- 自动点击、滑动、长按和文字输入。
- 多步骤任务规划。
- 跨 App 操作。
- 任务记忆与执行进度保存。
- 失败检测和自动恢复。
- 长时间运行的任务管理。
- 用户随时暂停、恢复和停止。

### 2. 游戏操作模式

支持：
- 游戏画面实时或准实时识别。
- 识别游戏界面、按钮、目标及状态变化。
- 根据当前局势自主制定策略。
- 连续执行多个动作。
- 本地动作队列和动作组合。
- 游戏状态验证。
- 失败后重新规划。
- 游戏任务长期运行。
- 网络中断和后台异常恢复。

优先针对 Galaxy 联合防御建立第一套游戏适配方案，同时保持通用游戏扩展能力。

游戏模式需要结合实际游戏画面进行开发，禁止虚构游戏按钮、坐标和玩法。

# 二、模型系统：必须支持动态模型列表

这是本项目的重点要求。

用户希望能够自由选择自己 ChatGPT/Codex 账号当前拥有使用权限的模型。

不要将模型名称写死在代码中。

### 模型管理要求

1. 优先通过 Codex app-server 获取当前账号可用模型列表。
2. 动态显示模型 ID、名称、可用状态和支持的推理参数。
3. 支持手动刷新模型列表。
4. 新模型出现时尽量自动识别。
5. 支持模型收藏和默认模型。
6. 支持每种任务独立设置模型。
7. 支持主模型和辅助模型。
8. 支持模型调用失败后的可配置回退。
9. 对不可用模型给出明确提示。
10. 保留未来兼容其他模型提供商的架构。

重点支持：
- GPT-6.1 Sol
- GPT-6.1 Terra
- GPT-6 Luna
- 未来 Codex 账号开放的模型。

上述模型以账号实际返回的可用模型列表为准。

### 思考程度设置

支持从模型元数据读取允许的推理程度。

提供：
- Minimal
- Low
- Medium
- High
- Extra High

具体选项必须服从模型实际支持范围。

### 模型路由

支持：
- 自动模式。
- 用户指定单模型。
- 双模型协作。
- 任务难度自动分配。
- 额度优先模式。
- 质量优先模式。

例如：

Terra：负责快速视觉分析、常规操作和结果验证。

Sol：负责复杂规划、困难决策和错误恢复。

必须允许用户关闭自动分配，完全手动选择模型。

禁止将模型名称、推理程度和服务等级当作永远不变的常量。

# 三、Codex 订阅认证与额度

优先研究 Mobile Codex 中的 Codex app-server 和 ChatGPT 账号认证实现。

目标：
- 用户通过支持的 ChatGPT 账号登录方式授权。
- 使用账号实际拥有权限的 Codex 模型。
- 使用对应的 Codex 订阅额度。
- 显示可获取的账户使用限制和额度信息。
- 监测请求失败、限流和模型不可用。
- 不要求用户额外购买 OpenAI API Token。

严格区分 Codex 订阅额度和 API 按量付费。

禁止通过伪造客户端身份、逆向绕过权限或不受支持的接口来实现账号接入。

若某种认证方式无法稳定复用，应先给出技术验证报告，再决定替代方案。

# 四、核心架构

采用模块化架构。

建议模块：

1. Android Application
2. Codex Runtime Adapter
3. Account Authentication
4. Model Registry
5. Model Router
6. Agent Orchestrator
7. Persistent Task Manager
8. General Agent Engine
9. Game Agent Engine
10. Vision Processing
11. Accessibility Controller
12. Action Executor
13. Action Queue
14. Checkpoint Manager
15. Recovery Manager
16. Watchdog
17. Safety Controller
18. Task Memory
19. Logging and Diagnostics

要求：

- 两种模式共享底层手机控制能力。
- 两种模式拥有独立的任务策略和执行状态。
- 同一时间只允许一个执行引擎控制手机。
- 任务管理独立于聊天界面生命周期。
- 任务状态支持持久化。
- 支持中断后恢复和状态重新验证。
- 支持完整执行日志。
- 所有操作具有超时和取消机制。

# 五、长周期 Agent 专项设计

这是项目最重要的技术挑战。

必须建立 Persistent Agent Supervisor。

至少实现：

### 任务持久化
记录：
- Task ID
- 当前阶段
- 当前目标
- 已完成步骤
- 待执行步骤
- 最近截图信息
- 模型调用记录
- 错误记录
- Checkpoint
- 用户授权状态

### Watchdog
监控：
- 模型请求超时。
- 连续失败。
- 操作没有产生预期变化。
- 手机控制服务中断。
- 网络连接异常。
- 应用进程异常。
- 长时间没有进度。

### Recovery Manager
能够：
- 恢复任务状态。
- 重新检查当前屏幕。
- 判断上次操作是否已经生效。
- 丢弃失效的操作队列。
- 重新规划剩余步骤。
- 在权限失效时等待用户重新授权。

### 运行要求

目标支持：
- 30 分钟任务。
- 60 分钟任务。
- 120 分钟压力测试。

这些是测试目标，不允许通过无限循环或无限重试伪造任务持续运行能力。

- Open App

- 执行结果。
